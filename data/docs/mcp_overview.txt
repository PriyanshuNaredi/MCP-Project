Model Context Protocol (MCP)

The Model Context Protocol, or MCP, is an open standard introduced by Anthropic that defines how AI applications connect to external tools, data sources, and systems. Before MCP, every AI application that wanted to integrate with a tool such as a file system, database, or web API had to write custom integration code for that specific tool. MCP standardizes this connection so that any MCP-compatible client can talk to any MCP-compatible server using the same protocol, similar to how USB-C standardized physical device connections.

An MCP system has two main roles: the host application (the client), which is the AI assistant or agent that wants to use tools, and the MCP server, which exposes a set of capabilities. An MCP server can expose three main types of capabilities: tools (functions the model can call, such as search_web or read_file), resources (data the model can read, such as file contents or database records), and prompts (reusable prompt templates the server provides).

Communication between an MCP client and server happens over a transport layer. The two most common transports are stdio, where the client launches the server as a subprocess and communicates over standard input and output, and HTTP with Server-Sent Events, used when the server runs remotely. Messages between client and server follow the JSON-RPC 2.0 specification, meaning every request has a method name and parameters, and every response has either a result or an error.

A typical MCP server implementation defines a list_tools handler that tells the client what tools are available, and a call_tool handler that executes a tool when the client requests it. The official Python SDK for MCP provides base classes such as Server, and helper functions like stdio_server for handling the stdio transport automatically, so a developer mainly needs to implement the handler logic for their specific tools.

MCP is particularly useful for building agentic systems, where a language model needs to decide which tool to call based on a user's query, call that tool, and incorporate the result into its response. Because the protocol is standardized, a tool built for one MCP-compatible agent can be reused by any other MCP-compatible agent without modification, which encourages a plug-and-play ecosystem of reusable tools rather than one-off integrations.
